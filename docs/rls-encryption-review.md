# RLS Compatibility Review

Sensitive profile fields are now protected at the application layer:

- `profiles.email` stores AES-256-GCM ciphertext.
- `profiles.full_name` stores AES-256-GCM ciphertext.
- `profiles.email_hash` and `profiles.full_name_hash` store keyed HMAC-SHA256 lookup hashes.
- `user_activity_logs.ip_address` stores AES-256-GCM ciphertext.

RLS policies should continue to authorize by stable identifiers such as `profiles.id`
or `user_activity_logs.user_id`, not by decrypted PII. Policies that compare on
`email` or `full_name` should be replaced with comparisons on `auth.uid()` or the
lookup hash generated by the app.

Expected policy shape:

```sql
-- profiles
USING (id = (select auth.uid()))
WITH CHECK (id = (select auth.uid()))

-- user_activity_logs
USING (user_id = (select auth.uid()))
WITH CHECK (user_id = (select auth.uid()))
```

Do not decrypt in RLS. PostgreSQL never receives `ENCRYPTION_KEY` or `HASH_KEY`.
